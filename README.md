# otp-relay

把手机收到的短信验证码，经**局域网**转发到电脑，自动识别、自动进剪贴板，还带一个能按 `Ctrl+Alt+V` 直接粘贴的热键。

不经过任何云端、不接任何接码平台、不需要账号。

```
 ┌─────────┐   短信    ┌──────────────┐   HTTP POST   ┌──────────────┐
 │ 你的手机 │ ────────▶ │ SmsForwarder │ ────────────▶ │  otp-relay   │
 └─────────┘           │  (转发 App)   │  局域网 8788   │  (本机 PS)    │
                       └──────────────┘               └──────┬───────┘
                                                             │
                                    识别 4~8 位验证码 ────────┤
                                                             ├──▶ 剪贴板
                                                             ├──▶ 右下角弹窗
                                                             └──▶ 网页面板 /api/history
```

## 为什么做这个

在电脑上登录网页、做 2FA 的时候，每次都要「掏手机 → 亮屏 → 解锁 → 找短信 → 看一眼这 6 位数字 → 手输」。一天十几次。

现成的接码平台要把短信内容交给第三方，而密码管理器大多不支持中国银行的短信格式。这个工具只做一件事：**让验证码出现在你电脑的剪贴板里**，全程走你自己的局域网。

## 环境要求

- Windows（用了 `System.Windows.Forms` 的通知和剪贴板，不支持 Linux/macOS）
- PowerShell 5.1 及以上（系统自带）
- 手机和电脑连同一个网络
- 手机上装一个能发 HTTP 请求的短信转发 App（推荐开源的 **SmsForwarder**）

## 快速开始

```powershell
# 1) 启动（带窗口，方便看日志）
.\debug-run.cmd

# 2) 看控制台打印出来的地址，形如：
#    http://192.168.x.x:8788/sms
```

然后用浏览器打开 `http://192.168.x.x:8788`，页面上点 **「发一条测试短信」**：

- 右下角弹出提示
- 剪贴板里出现 `831204`

电脑端就通了。接下来配手机，见 [docs/手机端配置.md](docs/手机端配置.md)。

启动方式有三种，按需选：

| 文件 | 用途 |
|---|---|
| `debug-run.cmd` | 带窗口运行，排错时用这个 |
| `start-hidden.vbs` | 后台静默运行（可放进启动文件夹做开机自启） |
| `stop-otp.cmd` | 停掉占用 8788 端口的进程 |

第一次运行如果手机连不上，双击 `allow-firewall.cmd` 放行 TCP 8788（会弹 UAC）。

## 快捷键

验证码收到并复制之后，在任何窗口按：

| 快捷键 | 行为 |
|---|---|
| `Ctrl+Alt+V` | 把最新验证码复制到剪贴板，并自动粘贴进当前输入框 |

> 自动粘贴是靠模拟 `^v` 实现的，个别以管理员权限运行的窗口（比如任务管理器、UAC 弹窗）收不到模拟按键，改用 `Ctrl+V` 手动粘贴即可。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/sms` | 接收短信。body 可以是纯文本，也可以是 `{"from":"...","content":"..."}` |
| `GET` | `/sms?content=...&from=...` | 同上，查询串形式（有些 App 只会发 GET） |
| `GET` | `/` | 网页面板：最新验证码、运行状态、历史记录 |
| `GET` | `/api/latest` | 最新一条记录（JSON） |
| `GET` | `/api/history` | 最近 30 条（JSON） |
| `GET` | `/api/status` | 端口、本机 IP、计数、配置状态 |
| `GET` | `/health` | 返回 `ok`，给探活用 |

请求体不用严格挑格式：服务端会把整个 body 扫一遍找数字，`from` / `sender` / `phone` / `address` 等字段名都能识别。

## 验证码识别的规则

简单说：**先找关键词附近的数字，再按上下文打分**。

1. 关键词（`验证码` / `校验码` / `动态码` / `OTP` / `verification code` …）后面 24 个字符内的 4~8 位数字，直接给 100 分。
2. 其余所有 4~8 位数字按长度给基础分（6 位最高）。
3. 再按上下文加减分：后面跟着「元 / 万 / GB / 天 / 次」的（金额、流量、天数）扣 45 分；前面是「订单 / 编号 / 手机 / 工单」的扣 35 分；看起来像年份（19xx/20xx）、纯重复数字（000000）再扣分。
4. 最高分且 ≥45 才认为是验证码，否则弹「没识别出验证码」，但原文照样进历史记录。

识别不准的时候，改 `config.json` 里的 `keywordPattern` 就行，不用动代码。

## 配置（config.json）

```jsonc
{
  "port": 8788,                 // 监听端口
  "autoCopyOnReceive": true,    // 收到就复制到剪贴板
  "autoPasteAfterHotkey": true, // Ctrl+Alt+V 后自动粘贴
  "keepHistory": 100,           // 保留多少条历史
  "keywordPattern": "验证码|校验码|..." // 识别关键词正则
}
```

改完重启生效。界面文案在 `strings.json`，想换语言改那里。

## 安全边界

- 服务只**接收**请求，不主动外连，不向任何服务器上报数据。
- 短信原文和验证码只存在本机 `data\history.json`，上限 `keepHistory` 条。
- **不要在公网暴露 8788 端口**，不要做端口映射。它没有鉴权，设计前提是「只在一个你信得过的局域网里」。
- 公共电脑上别开。公司网络如果做了「客户端隔离」，手机连不到电脑，用 USB 共享网络绕一下。
- 剪贴板是所有程序都能读的，验证码从进剪贴板那一刻起就不算秘密了 —— 这是这个工具的设计取舍：**方便优先**。用完可以把 `autoCopyOnReceive` 设成 `false`。

## 已知限制

- 只支持 Windows。
- 用的是手写的 `TcpListener` HTTP 解析，不是完整 HTTP 服务器：只支持 `Content-Length` 和 `chunked` 两种请求体，不支持 keep-alive。
- 通知用的是 `NotifyIcon.ShowBalloonTip`，在 Windows 11 上会走系统通知中心，样式随系统版本变。
- 取验证码是启发式的，总有识别错的时候，所以界面上永远显示短信原文兜底。
